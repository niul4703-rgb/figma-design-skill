# 视觉稿驱动的 Figma 系统设计

把视觉稿转成可复用规范、组件和素材，经样板确认后用于页面还原和系统扩展。完成依据是实际 Figma 节点及导出，不以命令成功、生成图片或其他 HTML 实现代替验收。

## 入口与范围

| 任务 | 路径 |
|---|---|
| 新视觉稿、新体系 | 分析 → 规范、代表组件及素材 → 确认 → 代表页 → 确认 → 扩展 → 验收 |
| 已有规范或组件库 | 检查并复用，仅补缺项；有新方向时再做样板 |
| 新增系统页面 | 依据原型或需求，应用已确认体系并验证必要状态 |
| 局部修正、续做 | 读当前节点及简短记录 → 修改受影响范围 → 复查，不重走全流程 |
| 仅分析、评审 | 输出发现与建议，不写入设计文件 |

明确输入类型、目标平台、交付范围和修改边界。按需记录参考稿、文件／Page／分区／画板、是否允许复制、尺寸及下限、保留区域、确认样板与素材限制。没有通用固定尺寸、颜色或间距；从项目中提取。用户最新要求优先，已有确认持续有效。

视觉稿主要决定外观，原型与需求主要说明功能、字段和流程。区分明确要求、已确认方案、未接受建议。冲突用“位置、依据、建议、影响”说明，不借统一规范删除功能或改变业务逻辑。

## 1. 分析视觉、业务与素材

新项目读取[视觉与素材分析](参考资料/视觉与素材分析.md)。识别结构、信息层级、重复模式、基础视觉参数与独立素材，区分明确值、估计值和设计建议。先核对截图缩放与实际画板对应关系。

输出适量的规范初稿、组件／素材清单和关键疑问。涉及系统扩展时建立页面与必要状态清单；只有一张视觉稿时，不能凭空发明全系统功能。

## 2. 建立规范、代表组件与素材

读取[组件与系统设计](参考资料/组件与系统设计.md)。先提取必要基础参数，制作代表组件，再结合内容验证修正规范。优先复用现有组件、变量和确认素材，仅补本任务缺项。

素材优先级：原始资产 → 合适的原生矢量／SVG → 必要的生成位图。SVG无法达到复杂光影、立体质感或纹理效果时，调用当前可用且获准的图像生成能力制作独立PNG；先确认代表素材，再扩展同系列。不用Emoji、字符或临时方块冒充图标，不切割整页截图充当可编辑控件。

**确认点一：** 展示实际规范板、代表组件与需要确认的素材，说明主动优化及影响。会话已有认可或明确授权可覆盖确认；不把沉默当作同意。普通复用不反复询问。

## 3. 还原完整代表页

通过用户指定连接方式实时核对目标、能力和字体，工具参数以当前接口为准。用户选择本仓库的自有插件时，先读取[配套连接器](参考资料/配套连接器.md)并核对安装、会话认证与实际能力；不绑定固定本机路径，也不强制替代其他兼容工具。连接、SVG导入、图层和部分写入问题按[还原细则](参考资料/还原细则.md)处理。

用确认组件和素材组成代表页面，保留字段、操作、内容层级与可见状态。文字、矢量、组件和图片保持正确分离；不拉伸文字或图标凑比例。

写入前明确节点清单、父级、可见性及实例关系；不能仅凭名称或坐标范围批量隐藏／移动。保留必要快照，分区写入并验证。未经授权不修改影响范围外页面的共享主组件。

**确认点二：** 导出实际完整页面，与参考同屏检查比例、密度、素材和完整性，说明差异。样板通过后持续扩展，仅新的关键分歧需要询问；不把组件单独通过等同于整页通过。

## 4. 扩展系统与处理反馈

有视觉稿的页面按稿还原；只有原型／需求的页面沿用已确认视觉体系。原型用于核对功能，不能机械覆盖已认可的视觉布局。

按[组件与系统设计](参考资料/组件与系统设计.md)处理内容变化、必要状态、响应式、滚动和交互说明。未知业务规则列出并核实，不伪装成已确认需求。静态页面、原型连线和运行系统分开报告。

反馈先判断影响单实例、同类组件或全系统，验证代表处后应用到受影响页面。保留用户手动修改，不执行过期脚本覆盖当前状态。已授权范围内的常规修复自主完成。

## 5. 验收与交付

读取[验收与交付](参考资料/验收与交付.md)，检查视觉、功能完整性、可用性及文件结构。尺寸下限优先于局部留白优化；不能为去留白缩短标准画板、拉伸行高或编造业务数据。

逐页查看当前实际导出，通用组件通过后抽查复用实例，复杂与修改区域重点检查。补修后重导出受影响页面并同步预览。明确自查通过、用户定稿和未解决项，不混称完成。

交付提供定位或实际导出、简短变更与限制。接续仅记录约束、定位、确认差异、素材来源、待处理项及最新产物，不修改无关Todos，不堆积每步报告。

## 项目知识隔离

项目约束、私有路径、连接配置、客户资料和节点定位保存在项目自己的记录中，不写入通用技能。使用前核对当前授权与状态。编码、部署、发送给第三方不由本技能默认授权。
