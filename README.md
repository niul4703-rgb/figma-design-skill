# Figma Design Skill

以视觉稿为起点，分析视觉与素材，建立规范和组件，经样板确认后还原可编辑 Figma 页面，并根据原型或需求扩展系统设计。

这是一套中文 AI agent 工作流指令，不是 Figma 插件、独立应用或自动生成引擎。它需要宿主提供相应的 Figma 读取、编辑、导出能力；生成 PNG 时还需要可用的图像生成工具。仓库不包含连接插件、API 凭据或客户素材。

## 功能

- 视觉稿分析：结构、字体、颜色、间距、组件及素材。
- 素材决策：原始资产、SVG 或 PNG；需要时生成代表素材并确认系列风格。
- 规范与组件：复用现有设计系统，建立必要样式、属性和状态。
- 页面还原：在 Figma 中制作可编辑页面，以实际导出对照验收。
- 系统扩展：根据原型和需求补充页面、必要状态、内容适配及交互说明。
- 安全修改与交付：限定目标范围，处理部分写入恢复，检查关联页面与交付限制。

## 安装

将本仓库的 `skills/figma-design` 整个目录复制到宿主的个人技能目录。Codex 的常见位置为 `~/.codex/skills/figma-design`；自定义环境请使用自己的技能目录。已有同名技能时先备份，再选择更新，不要直接覆盖个人项目经验。

```text
skills/figma-design/
├── SKILL.md
├── agents/openai.yaml
└── 参考资料/
    ├── 视觉与素材分析.md
    ├── 组件与系统设计.md
    ├── 还原细则.md
    └── 验收与交付.md
```

## 使用示例

```text
使用 $figma-design，分析我提供的视觉稿。
先制作设计规范、代表组件和必要素材，给我确认；
然后还原完整样板页，确认后再根据业务原型扩展其他页面。
仅修改我指定的 Figma 分区。
```

请同时提供视觉稿，以及需要时的目标平台、尺寸约束、Figma 目标文件和业务原型。已有规范或局部修改会采用精简流程。

## 工作流程

视觉与需求分析 → 规范／组件／素材 → 确认 → 完整样板页 → 确认 → 系统扩展 → 验收。

确认过的约束会持续复用。缺少业务依据时不自行发明系统功能，也不保证任何截图都能达到像素级一致。

## 范围与成熟度

- 当前是工作流指令版本，结构与引用已检查；不宣称已在所有宿主、连接器或新项目中验证。
- Figma 写入、图像生成和原型连线取决于宿主工具及授权。没有工具时不能仅凭安装此技能实现这些能力。
- 默认不包含代码开发、部署或发送给第三方。
- 不附带客户设计、商业素材或项目专属参数。用户应确认输入素材可用于对应任务。
